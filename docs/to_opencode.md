## Goal and proof boundary

Prove two-way UDP6 **Message/datagram** semantics without any `Chan`, `namec`, `chandial`, file path, `#I` file dispatch, `Netfile` subscription or new userspace ABI on the tested UDP6 path:

```text
HOST UDP6 datagram inside a real Ethernet/IPv6 frame
  -> QEMU VirtIO real NIC RX
  -> E7.1 etheriq / E7.2 native RX worker
  -> existing ipiput6 -> existing udpiput (udp Proto)
  -> native bound UDP6 endpoint / message queue
  -> in-kernel E7.3 echo fixture reads ONE complete datagram + peer metadata
  -> native UDP6 send-to (reuse existing udpkick / UDPv6 checksum/output)
  -> existing ipoput6 -> E7.2 native medium
  -> ethercore_tx -> real VirtIO TX
  -> host verifies IPv6+UDP headers, checksum, ports and unchanged payload
```

**Required end result:** With a fixed test-only guest link-local address and UDP port, a host sends multiple UDP6 datagrams; the guest returns distinct UDP6 datagram echoes from the same bound port to the correct host source address/port. The host verifies the *actual* outbound Ethernet frames and UDP6 checksums, and guest counters identify the existing `udpiput` and `udpkick` paths. An echo generated by manually building a UDP/IPv6 header in a parallel implementation does not pass.

A native UDP6 endpoint is a **kernel C capability**, not a user-visible socket or file. Do not confuse the existing `Conv` internal data structure with a new ABI. Exact proposed function names are flexible, but the public C contract must be **typed, small, explicit and documented**: create/bind UDP6 endpoint, send a Message to an explicit IPv6 peer/port, receive a complete Message plus sender/destination metadata, close/stop. Include ownership, queue/backpressure, error and call-context semantics. This is groundwork for later WireGuard outer UDP6; **do not implement WireGuard in E7.3**.

## E7.3.1 — bounded E7.2 lifecycle corrections (must precede UDP endpoints)

Before letting a service own any UDP `Conv`, close the E7.2 hazards observed in review:

1. `ipv6native_stop` currently clears `nativeone` **before** the worker has definitively exited and can return `EtherErrOk` after an approximately 2-second timed wait even if the worker is still running. Implement an explicit synchronized RUNNING/STOPPING/STOPPED lifecycle or equivalent. Reject start during STOPPING, stop receiving new frames, quiesce the RX callback, close the RX queue, wake the worker, and report success **only after the worker has fully exited**. If a bounded stop times out, return an error and retain ownership/state; never expose a half-stopped instance as fully stopped. No stale worker may touch reused/free storage.
2. `ipv6native_start` returns after partial allocation failure without cleaning `Fs`/`Ipifc`/`Conv`/queues. Implement correct rollback for feasible stages, including the worker and RxSink. Inspect dependencies before freeing shared protocol structures; if full destruction is unsafe due to inherited kernel workers, use an explicitly documented terminal one-shot state and fail a restart cleanly rather than leaking an unbounded number of protocol stacks. **Do not invent a broad Fs destructor framework** in this task.
3. Ensure any UDP endpoint and echo worker close *before* tearing down the IPv6 medium/Fs and cannot be used after close. A blocked `qbread`/receive must be woken on close. Define cancellation and Block ownership for aborted sends/receives.
4. Keep E7.2's packet-path and E7.1's hardware tests unchanged in meaning. Add focused start-failure (where injectable without unsafe fault injection), repeat start, stop, repeat stop, stop/start or explicitly safe no-restart tests.

If lifecycle fixes require a large unrelated redesign, mark **PARTIAL-HOLD**, implement only sound bounded fixes, and clearly state why safe UDP endpoint teardown cannot yet be promised.

## E7.3.2 — one native UDP6 API backed by existing UDP Proto/Conv

Implement the smallest possible *direct kernel C* UDP6 entrypoints for one or more bounded endpoints. Recommended shape (adapt names/types to the source as necessary):

```c
/* Illustrative contract, NOT prescribed ABI */
Udp6Endpoint *udp6_open(Ipv6Native *network, ushort local_port);
int udp6_recv(Udp6Endpoint *, /* Message + src IPv6, src port, dst IPv6, dst port */);
int udp6_sendto(Udp6Endpoint *, /* peer IPv6 + peer port, payload Message */);
int udp6_close(Udp6Endpoint *);
```

- Back this with `network->f->t2p[17]` and real `Fsprotoclone` plus UDP `Proto` and `Conv` lifecycle. Binding must correctly put the `Conv` in the inherited `udpiput` lookup/hash (prefer the existing `udpannounce`/`udpconnect` and `headers` semantics rather than duplicating `iphtadd` logic). Enforce **IPv6-only** address family, explicit bound local address (test guest link-local), local port nonzero, duplicate-bind conflict handling and at least two independently distinguishable source peers/ports. No IPv4-mapped surprise fallthrough.
- Receive exactly **one UDP datagram per Message**, including sender IPv6 and UDP source port, local destination IPv6 and local destination port. Preserve zero-length payloads. Never concatenate separate datagrams into a stream and never return a partial successful datagram. Define what happens if the caller's provided buffer is too small: reject with required length or receive a full owned Block, not silent stream-style fragmentation. Keep bounded `Qmsg` queues and explicit dropped/error counters.
- Send to a specified IPv6 destination+port using the same `Conv`, existing `udpkick` checksum construction, `ipoput6` and native E7.2 medium/`ethercore_tx`. Do not create an independent UDP header encoder as the operational path. Make `Block` transfer/cleanup explicit. The public C API must distinguish at minimum bad argument, closed endpoint, not bound, too-large datagram, unavailable route/neighbor, queue full and successful acceptance. Where inherited asynchronous `udpkick` cannot report actual NIC transmission, explicitly distinguish “accepted for delivery” from “transmitted”; test both packet bytes and counters.
- Avoid unnecessary `Fsnewcall`/`listen` children for a datagram listener. Ensure `UDP.headers==7` semantics or an equivalently small adaptation keeps a single listener and preserves per-datagram peer metadata. Do not create one `Conv` or one worker per received Message.
- Serialize close vs send/receive and UDP `Proto` lookup so `udpiput` cannot enqueue into a freed endpoint/queue. Reuse or explicitly strengthen the existing `Conv` lock/queue lifecycle rather than replacing it. Make flow-control and backpressure behavior observable.
- Retain legacy `#I` UDP4/UDP6, TCP/IP, routing and `#l` behavior in standard profiles. No global removal of the existing `udp.c` dual-stack logic or `Proto`/`Conv` internals.

A fixed test-only UDP6 echo service using the new entrypoints is appropriate; it must not be wired into the regular O-server boot or MicroPython ABI yet. Use an opt-in `pc64e73` profile or similarly isolated continuation profile: build and boot dispatch must not change normal defaults.

**Mandatory positive hardware evidence** from one QEMU guest:

1. E7.3 native service binds test-only guest `fe80::...` port `20001` using the direct C endpoint API. A host sends an ICMPv6 NS, guest returns valid NA as in E7.2. Host knows guest MAC/IP before UDP traffic.
2. Host sends valid IPv6 UDP requests from at least **two different UDP source ports** to guest port 20001. Echo returns to the correct IP/port each time with source port 20001; the guest's payload replies are produced by the **existing UDP send path**. Validate exact Ethernet+IPv6+UDP header fields, nonzero valid UDP6 pseudoheader checksum, UDP length and payload, correlated IDs, and no duplicate or cross-routed responses.
3. Test payload lengths `0`, `1`, `17` and a near-MTU but nonfragmenting payload (choose using computed actual MTU/IPv6/UDP headers). Exercise repeated Messages in a single session without rebind, and verify message boundaries even when packets arrive quickly.
4. Show instrumented guest counters or narrowly placed markers for `udpiput` receive → bound endpoint queue → application receipt → `udpkick` → `ipoput6` → `ethercore_tx`. Host-side response bytes remain the primary proof.
5. Repeat native path `namec/newchan/walk/devwalk/mount/exec` snapshots for the UDP bind, receive and reply window. No new `Chan` operation on the demonstrated native chain. Source inspection must complement counters.

**Mandatory negatives (real NIC unless explicitly isolated):**
- No controller boot must not panic; default without E7.3 opt-in must not start a UDP echo service.
- Send valid UDP6 to an **unbound port**: no echo; validate the inherited expected ICMPv6 Port Unreachable if emitted rather than demanding silence. Check no unintended `Conv` allocation.
- IPv4 EtherType frames not dispatched into native UDP6, and no acceptance of IPv4-mapped UDP endpoint addresses.
- UDP6 **zero checksum** and corrupted checksum rejected; mismatched UDP length (too short, too long), truncated header/payload, wrong IPv6 payload length rejected without kernel fault. Validate any rejection with subsequent good datagram (ALIVE).
- Duplicate binding to the same local address/port rejected or clearly defined as controlled reuse; no silent second active listener.
- RX queue saturation / backpressure and closed-endpoint send/receive; no successful send or delivery after close. Close with pending datagrams must wake waiting process(es) and avoid stale `Conv`/Block ownership.
- TX link down/queue full/closed: verify result as far as actual kernel semantics permit, distinguishing test of an isolated queue primitive from proof against the real NIC.
- Probe repeated native start/stop and UDP endpoint lifecycle; no unbounded growth in active UDP `Conv` objects or workers. If safe IPv6 restart is explicitly unsupported, confirm deterministic error, not a spurious success.

Host fixture MUST fail on unexpected frames, wrong checksums/ports/payload, positive timeouts, guest panic and missing expected code-path evidence. Do not fake success with synthetic `Block` injection or log-grep-only assertions.
